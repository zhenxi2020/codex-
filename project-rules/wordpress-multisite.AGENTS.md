# WordPress 多站点工作区规则

本工作区继承 `C:\Users\Administrator\.codex\AGENTS.md`。本文件用于防止多个站点和 WordPress 核心目录之间发生误改。

## 工作区边界

- `斋名堂/` 与 `wurent/` 是不同站点工作区；每次确认单必须写明目标站点和目标环境。
- `wordpress-7.0-zh_CN/` 及其 ZIP 是 WordPress 核心分发文件，除非任务明确要求研究核心，否则不得修改。
- 仓库可能存在大量用户未提交文件。开始任务先运行 `git status --short`，只处理确认范围内文件，不清理、不暂存、不覆盖其他改动。
- `dist/`、`output/`、截图、备份、浏览器配置和发布包是产物或证据，只有任务明确要求时才生成或更新。

## WordPress 实施规则

- 优先修改目标站点的主题、插件或 mu-plugin，不直接修改 `wp-admin`、`wp-includes` 等核心文件。
- 可维护内容优先使用后台、原生配置、已有字段或设置页，避免在模板中写死。
- 修改公共函数、菜单、路由、重写规则、数据库字段或站点 URL 前，确认影响范围和回滚方式。
- 服务器、数据库、生产站和部署动作必须在确认单中单独列出；本地授权不自动包含线上修改。

## 验证

- PHP 改动先做相关文件语法检查，再验证目标页面或后台入口。
- 共享模板或全局样式变化至少检查一个桌面端和一个移动端代表页面。
- 数据或设置变化验证保存、刷新、空值、旧数据与失败回滚。
- 未经明确要求，不部署、不切站、不升级 WordPress、不制作发布包。

## 文档路由

- 进入具体站点后，优先遵循该站点更深层的 `AGENTS.md`。
- 只读取当前任务相关的 `tasks/`、`docs/` 和最近教训，避免加载整个工作区历史。
